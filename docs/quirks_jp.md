# ハードウェアの癖

(英語版: [quirks.md](quirks.md))

レジスタの説明からは分からず、見つけるのに時間がかかったものです。どれも
ドライバで対処済みです。

## ROT0 は DRAM の低い位置しか読めない

イメージのバッファが 4 GB 以内でも高い位置にあると、ROT0 はファームウェアの
読み込みをステータス `0x3ff` で拒否します。`0xfa000000` 付近は失敗し、
`0x80080000`〜`0x80e00000` は成功しました。IORT では ROT0 のアドレス上限は
32 bit となっているのに、です。ページアロケータはどちらの位置も返すので、
「warm reboot すると壊れる」というランダムな問題に見えていました。
`surface_ccu_boot` はバッファの候補を 64 個取って一番低いものを使い、それでも
拒否されたら別のバッファで再試行します。

## センサーのクロックは 19.2 MHz ではない

OV02C10 の 2 レーン用モード表(HTS 1140、VTS 2328)は 19.2 MHz の MCLK で
30 fps になる設計ですが、このマシンでは 18.8 fps になります。1 ラインの時間は
22.8 µs で、これはクロックが約 12 MHz だと考えると合います。PLL には手を
付けず、フレーム長を VTS 1462 に縮めてちょうど 30 fps にしています。最大露出は
VTS - 8 です。

## CCU 起動直後の最初のストリームは経路がつながらない

CCU ファームウェアが起動した直後の最初のストリーム開始では、経路が
つながりません。mac_csi はフレームをデコードしていますが、どの outmux にも
データが届きません。同じ手順でも 2 回目からはつながります。ドライバは
outmux1 までデータが届いているかを確認し、届いていなければ一度だけ
ストリームをやり直します。

## outmux のレジスタは二重バッファで、0 にも意味がある

outmux の設定は `SW_CFG_DONE`(`+0x1c`)を立てて初めて有効になります。
ハードウェアはフレームの区切りで値をラッチすると、このビットをクリアします。
そのため、ストリーム中のシステムのレジスタダンプでは 0 に見えてしまい、
見落としやすいです。

`SRC_SEL`(`+0x18`)と `SOURCE_CONFIG_0`(`+0x0c`)のリセット値は 3 で、
これは「未使用」を意味します。ファームウェアはセンサーの経路を決めるとき、
センサー選択が 2 以上の outmux を飛ばします。Windows は使う outmux(1 と 7)に
0 を書き込み、それ以外は 3 のままにしています。つまり、レジスタダンプの
0 以外の値だけを再現すると、ファームウェアが決して経路を作らない設定に
なってしまいます。

## camsv_b には専用のクロックが要る

Windows が使っている camsv は、camsv_a ではなく `0x3A510000` の camsv_b です。
camsv_b には clarb13(`0xa00`)と camsv_b(`0xa18`)のクロックが必要で、これが
無いと書き込みはすべて黙って捨てられ、読むと 0 が返ります。

## フレーム単位の DMA レジスタはレジスタダンプに出てこない

Windows は camsv の DMA アドレス、ストライド、FBC を、コマンドキュー経由で
フレームごとに内側の(実際に使われる)レジスタバンクへ直接書き込みます。
そのため、外側のレジスタのダンプでは 0 に見えます。ドライバは外側の
レジスタに書き込み、各フレームの開始時に二重バッファの読み込みでラッチ
させています。また、camsv の DMA ブロックの `0x000-0x01c` は閾値の設定で、
アドレスではありません。

## 電源の落ちたブロックを読むと CPU が固まる

電源ドメインが切れているカメラブロックを MMIO で読むとバスがストールし、
そのタスクは kill できなくなります。ストリーム開始時は、どのカメラレジスタに
触れるよりも先に HFRP に電源ドメインを依頼しているので、システムの
サスペンド後でも安全です。

## 標準の ov02c10 ドライバはブラックリストに入れている

mainline の `ov02c10` も同じ ACPI デバイスにバインドしますが、このマシンでは
センサーに給電できず(INT3472 もクロック供給元も無い)、GPIO の取り合いに
なります。

## その他

- ストリーム開始時に FBC のリセットビットを書いてはいけません。フレームが
  来なくなります。
- `SOF_STATUS` と `DONE_STATUS` は読むとクリアされるので、診断のための読み出しで
  触ってはいけません。
- v4l2loopback 経由だと、`v4l2-ctl` は最初のうち fps を低く表示します。最初に
  受け取るバッファが、sucamd が起動時に書いた古いタイムスタンプの待機用
  フレームだからです。実際は 30 fps 出ています。
